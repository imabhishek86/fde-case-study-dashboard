# 08. Proposed 30-60-90 Day Implementation Roadmap

> [!IMPORTANT]
> **Roadmap Context:** This roadmap represents a **proposed technical sequence** derived from public review evidence and multi-dimensional issue prioritization. Actual scheduling, sprint velocity, and milestone delivery depend on MoveInSync's internal engineering team capacity and corporate client priorities.

---

```
[Phase 1: Days 1–30] ─────────> [Phase 2: Days 31–60] ────────> [Phase 3: Days 61–90]
  Instrumentation,                Core Engine Remediation,        Algorithmic Scaling,
  P0 Emergency Investigations     UI Thread Profiling &           Operational Governance &
  & Rapid Quick Wins              UX Hardening                    Rating Trend Evaluation
```

---

## Phase 1: First 30 Days — Instrumentation, Emergency Fixes & Quick Wins

### Core Objective
Establish baseline observability across P0 failure points, deploy zero-risk UX Quick Wins to halt negative review velocity, and isolate emergency launch crash bugs.

### Key Milestones & Deliverables
1. **App Startup Crash Investigation (P0):**
   - Extract Google Play Console Android Vitals and Crashlytics startup stack traces for the last 3 production builds.
   - Isolate whether startup failures are driven by Room / SQLite database migration exceptions, native crashes, or OEM-specific lifecycle bugs.
   - If a specific migration bug is identified, prepare and deploy an immediate targeted hotfix release.
2. **Deploy Dismissible Rating Prompt (P1 Quick Win):**
   - Add a visible "Skip" / "Dismiss" button to the post-trip rating prompt.
   - Ensure dismissal does not block navigation to scheduling or roster tabs.
   - Launch A/B experiment monitoring rating modal completion vs Play Store review trends.
3. **Refactor Boarding Safety Prompt (P0 Quick Win):**
   - Convert blocking seatbelt modal into a non-blocking inline advisory on the boarding screen.
   - Enable single-click OTP visibility to eliminate curbside boarding gate friction.
4. **Instrument End-to-End GPS Freshness Pipeline (P0):**
   - Deploy timestamp logging across all 6 telemetry hops (Driver GPS → Ingestion → Broker → Dispatch → Client Receipt → UI Render).
   - Establish baseline P50, P90, and P95 location age distributions during peak commute hours.
5. **Instrument Booking APM Tracing (P0):**
   - Deploy transaction-level APM tracing on the booking microservice to measure error rates and database lock contention during the final 15 minutes of shift cutoff windows.

---

## Phase 2: Days 31-60 — Core Engine Remediation & UX Enhancements

### Core Objective
Remediate confirmed technical bottlenecks in Booking Reliability and Live GPS Tracking, eliminate client UI thread lag, and harden authentication lifecycle.

### Key Milestones & Deliverables
1. **Booking Reliability Hardening (P0):**
   - Deploy client-side idempotent booking request submission to eliminate duplicate calls and race conditions.
   - Implement explicit client booking state machine (`REQUESTED`, `ALLOCATING`, `CONFIRMED`, `WAITLISTED`).
   - If backend APM confirmed DB connection pool saturation, scale connection pool and optimize cutoff query execution plans.
2. **Live GPS Freshness Pipeline Remediation (P0):**
   - Remediate the largest confirmed bottleneck identified in Phase 1 (e.g., driver app background location persistence, broker queue consumer lag, or client WebSocket reconnection logic).
   - Deploy UI freshness timestamp ("Updated 4s ago") and explicit stale-location state handling.
3. **App UI Thread Profiling & Freezing Mitigation (P0):**
   - Decouple coordinate stream parsing and local caching from the main UI thread to background worker threads.
   - Optimize map polygon and marker draw cycles to eliminate frame drops and ANR incidents on mid-tier Android devices.
4. **Silent Background Token Refresh & Offline OTP (P1):**
   - Implement silent access token rotation in `onResume` lifecycle transitions, preventing unexpected curbside logouts.
   - Securely cache active ride boarding OTPs in encrypted local storage for instant offline access in basement pickup zones.
5. **Routing Solver Simulation (P1):**
   - Run historical route datasets through updated solver models enforcing maximum allowable commuter detour ratio caps.
   - Evaluate fleet vehicle allocation impact in collaboration with transport operations teams.

---

## Phase 3: Days 61-90 — Algorithmic Scaling, Operational Governance & Rating Trend Evaluation

### Core Objective
Deploy tuned routing solver constraints and dynamic ETAs, establish operational fleet quality feedback loops, address secondary enhancements, and evaluate Play Store sentiment recovery.

### Key Milestones & Deliverables
1. **Deploy Routing Detour Limits & Dynamic ETA Calibration (P1):**
   - Roll out tuned solver constraints to select corporate tech park routes, capping excessive multi-zone detours.
   - Deploy 4-stage ETA calibration pipeline with dynamic multi-passenger boarding dwell buffers.
2. **Vendor Fleet Quality & In-Cabin Comfort Dashboard (P1):**
   - Deploy structured in-app feedback tags ("AC Not Working", "Cleanliness", "Rash Driving") for rides rated < 4 stars.
   - Launch vendor partner defect escalation dashboard to trigger physical maintenance inspections for repeat-complaint vehicles.
3. **Secondary Operational Enhancements (P2):**
   - Launch one-tap in-app exception reporting ("Report Delay") to streamline helpdesk ticket intake.
   - Configure Android `PRIORITY_HIGH` heads-up notification channels for vehicle approach alerts.
4. **Comprehensive Rating Trend & Roadmap Evaluation:**
   - Review 90-day Play Store rating distribution, monitoring shifts in 1-star review volume and complaint frequency across the 14 audited clusters.
   - Synthesize telemetry findings into the next quarterly product and engineering cycle.
